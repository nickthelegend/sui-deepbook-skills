# DeepBook V3: BalanceManager

`BalanceManager` is a shared object (`sui::object::UID`) in DeepBook V3 that holds and manages all user balances for various assets (both base and quote tokens). Except for direct swaps, almost all trading operations in DeepBook V3 require a `BalanceManager` as an input.

---

## 1. Key Concepts

### Shared Object Design
- **Single Manager for All Pools**: A trader can use a single `BalanceManager` across all pools they interact with (e.g. SUI/USDC, DEEP/SUI).
- **Settlement**: When orders match, funds are directly deposited into or withdrawn from the `BalanceManager`'s internal balances.

### TradeProofs and Equivocation
To execute any trade, you must provide a `BalanceManager` and a `TradeProof` to verify authorization. There are two ways to obtain a `TradeProof`:
1. **Direct Owner**: Generated directly by the owner of the `BalanceManager`. Since this does not require an owned object parameter (it operates on the shared manager itself with the transaction sender being the owner), there is **no risk of equivocation**. High-frequency trading (HFT) engines should always trade as the default owner.
2. **Cap Owner**: Generated by a holder of a `TradeCap`. Since `TradeCap` is an owned object, sending it in a transaction carries the risk of **equivocation** (double-spending or locking the object in consensus).

### Capabilities (Caps)
An owner of a `BalanceManager` can delegate operations by minting capabilities:
- **`TradeCap`**: Allows the holder to place, modify, or cancel orders for this `BalanceManager`.
- **`DepositCap`**: Allows depositing funds.
- **`WithdrawCap`**: Allows withdrawing funds.

> [!WARNING]
> The maximum combined number of `TradeCap`, `WithdrawCap`, and `DepositCap` objects assigned to a single `BalanceManager` is **1,000**. If this limit is reached, existing capabilities must be revoked using `revoke_trade_cap` before new ones can be minted.

## 2. On-Chain API (Move)

The `balance_manager` module in `deepbook` packages exposes these primary functions:

### Creation
- `public fun new(ctx: &mut TxContext): BalanceManager`
  Creates a new `BalanceManager`. Must be shared with `sui::transfer::share_object` in the same transaction.
- `public fun new_with_custom_owner(owner: address, ctx: &mut TxContext): BalanceManager`
  Creates a `BalanceManager` with a custom owner address. Must be shared.
- `public fun new_with_custom_owner_caps<App>(registry: &mut Registry, owner: address, ctx: &mut TxContext): (BalanceManager, DepositCap, WithdrawCap, TradeCap)`
  Creates a manager with custom owner and returns all three capability objects in one call. Requires registry authorization using the `App` witness.

### Deposit & Withdrawal
- `public fun deposit<Asset>(self: &mut BalanceManager, coin: Coin<Asset>, ctx: &mut TxContext)`
  Deposits funds into the manager (Owner only).
- `public fun withdraw<Asset>(self: &mut BalanceManager, amount: u64, ctx: &mut TxContext): Coin<Asset>`
  Withdraws funds from the manager (Owner only).
- `public fun deposit_with_cap<Asset>(self: &mut BalanceManager, cap: &DepositCap, coin: Coin<Asset>)`
  Deposits funds using a `DepositCap`.
- `public fun withdraw_with_cap<Asset>(self: &mut BalanceManager, cap: &WithdrawCap, amount: u64, ctx: &mut TxContext): Coin<Asset>`
  Withdraws funds using a `WithdrawCap`.

### Capabilities Management
- `public fun mint_trade_cap(self: &mut BalanceManager, ctx: &mut TxContext): TradeCap`
  Mints a trading capability (Owner only).
- `public fun mint_deposit_cap(self: &mut BalanceManager, ctx: &mut TxContext): DepositCap`
  Mints a deposit capability (Owner only).
- `public fun mint_withdraw_cap(self: &mut BalanceManager, ctx: &mut TxContext): WithdrawCap`
  Mints a withdrawal capability (Owner only).
- `public fun revoke_trade_cap(self: &mut BalanceManager, cap_id: ID)`
  Revokes a specific capability by ID. This function is also used to revoke `DepositCap` and `WithdrawCap` objects.

### Proof Generation
- `public fun generate_proof_as_owner(self: &mut BalanceManager, ctx: &mut TxContext): TradeProof`
  Generates a `TradeProof` (Owner only). Hot potato object; must be consumed within the same transaction.
- `public fun generate_proof_as_trader(self: &mut BalanceManager, cap: &TradeCap, ctx: &mut TxContext): TradeProof`
  Generates a `TradeProof` using a `TradeCap`.

### Registry & Referral Settings
- `public fun register_balance_manager(registry: &mut Registry, self: &mut BalanceManager, ctx: &mut TxContext)`
  Registers a balance manager in the DeepBook registry.
- `public fun set_referral(self: &mut BalanceManager, cap: &TradeCap, pool_id: ID, referral_id: ID)`
  Associates a pool-specific referral object ID with the manager.
- `public fun unset_referral(self: &mut BalanceManager, cap: &TradeCap, pool_id: ID)`
  Removes a pool-specific referral association.

## 3. TS SDK Usage Examples

Below is how to interact with `BalanceManager` using the `@mysten/deepbook-v3` SDK.

### Creating and Depositing Funds

```typescript
import { Transaction } from '@mysten/sui/transactions';
import { DeepBookClient } from '@mysten/deepbook-v3';

const client = new DeepBookClient(suiClient);

async function setupBalanceManager() {
    const tx = new Transaction();
    
    // 1. Create a new BalanceManager
    const balanceManager = client.newBalanceManager(tx);
    
    // 2. Deposit SUI into the newly created BalanceManager
    const [depositCoin] = tx.splitCoins(tx.gas, [10_000_000_000n]); // 10 SUI
    client.deposit(tx, {
        balanceManagerKey: balanceManager,
        coin: depositCoin,
        assetType: '0x2::sui::SUI'
    });
    
    // 3. Share the BalanceManager object
    tx.transferObjects([balanceManager], keypair.toSuiAddress());
    
    const result = await suiClient.signAndExecuteTransaction({
        transaction: tx,
        signer: keypair,
    });
}
```

### Delegation via Capabilities

```typescript
async function delegateTrading(managerId: string, traderAddress: string) {
    const tx = new Transaction();
    
    // Mint a TradeCap from the manager
    const tradeCap = client.mintTradeCap(tx, {
        balanceManagerKey: managerId
    });
    
    // Send the capability to the delegated trader
    tx.transferObjects([tradeCap], traderAddress);
    
    await suiClient.signAndExecuteTransaction({
        transaction: tx,
        signer: keypair
    });
}
```

## 4. Events Emitted

- **`BalanceManagerEvent`**: Emitted when a new balance manager is successfully created.
- **`BalanceEvent`**: Emitted on deposits or withdrawals, recording the change in token balances.
